# 任務總表（計畫 8）

`backend/content/missions.json` 共 21 筆：15 筆一般任務、6 筆每日任務；`monsters.json` 另有 3 隻任務怪。WOG 的主線任務全部存在資料表 `wog_mission_main`，SQL 已遺失（見 `wog-research-world.md` §2），一般任務是 Claude 的設計；每日任務移植自 `mission/wog_mission_{222,224,271～274}.php` 的模板規則。測試 `Tests/Content/MissionTableTests.cs` 釘住下列規則；改內容時本檔與內容檔一起改。

## 規則

- 一般任務：金錢 = `50 × level`，經驗 = `190 × level`（`MissionDefinition.Exp`，同 WOG `wog_mission_tool.php:208`）；`level` 同時是接取等級門檻。
- 一般任務分布在四個開放區域：中央大陸、魔法王國、熱帶雨林各 4 筆，末日王城 3 筆；禁區沒有任務（禁區要鑰匙，計畫 10）。
- 技能獎勵只給 Lv1，任務的 `requirements.jobId` 必須是該技能的職業。
- 每日任務沒有地區，目標池（`dailyKills`）與報酬池（`dailyRewards`）每天各擲一次；`rewards` 為空。
- 懸賞類（`daily-bounty-*`）的目標池是對應地區 `meet 0` 的怪（同 WOG `m_meet=0` 篩選），每隻怪各列 count 5、6、7 三筆（等同 WOG 的 `rand(5,7)`）；報酬原為交易所資源（多人），改發金錢 `round(level × 50 × f)`，`f ∈ {0.8, 1.0, 1.2}`。
- 載入驗證見 `JsonGameContent`（任務在怪物、道具、技能之後驗證，任務怪的 `missionId` 在任務載入後回頭檢查），每條規則都有 `JsonGameContentTests` 的拒絕測試。

## 與研究報告的差異

- **擊殺只計勝場**：同 PHP `wog_fight_select.php` 的勝場分支，敗北與 40 回合超限都不算。
- **PHP 同怪覆寫**：PHP 以怪物 id 為 key 記錄進度，同一隻怪是多個任務的目標時只算到其中一個；視為實作缺陷，這裡所有以牠為目標、尚未達成的進行中任務都 +1。
- **任務怪**：WOG 以 `wog_monster.m_mission` 篩選；這裡任務怪只在該任務進行中且尚未達成時出現，已達成、未接、已完成、已過期都不出現（含「沒有候選時退回全地區」的分支）。
- **NPC 計數 `m_npc`**：WOG 的 NPC 怪遇到即計數、不戰鬥，不做。
- **獎勵不檢查背包**：PHP 的 `item_in` 無視背包容量；這裡獎勵放不下就整筆拒絕（`bagFull`），不讓獎勵消失也不超量。
- **技能已會即報錯**：PHP 給已會的技能會報錯、任務卡死；這裡略過技能、其餘照給。
- **經驗不升級**：PHP 只加 `p_exp`，下一場戰鬥才升級；這裡加完經驗立刻套用升級。
- **過期每日紀錄連進行中一起刪**：WOG 每次讀取都 `DELETE` 過期的每日紀錄，不論狀態；這裡過期紀錄同樣一律視為不存在，寫入時順手刪除。
- **目標與報酬分開擲**：同 WOG，每日任務的目標池與報酬池各擲一次（這裡以角色、任務、週期日期為種子，每天每角色固定）。
- **WOG 進度顯示剩餘數**：WOG 的「任務進度：」顯示剩餘數，這裡改顯示已完成數 `{progress}/{required}`。
