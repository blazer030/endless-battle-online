# 計畫 11：旅館 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 旅館的功能面：
- 手動入住拿 8 小時的房型加成。加成跟密藥相乘，同時只有一種房型。
- 在旅館頁調整自動住宿門檻。
- 前端是背包頁的一個子頁，畫面先求能用。

**Architecture:** 沿用既有分層。
- **內容**：房型放在新內容檔 `inn.json`。
- **Domain**
  - 入住、價格、房型加成的規則放在 `Domain/Rest/Inn.cs`。
  - 加成相乘放在 `Buffs`。
- **資料表**：新表 `character_lodgings`，每個角色一列。
- **Application**：`InnService` 提供查詢與入住。入住照密藥的做法，先 `AdvanceAsync` 結算，再寫入。
- **推進**：`AdventureService` 推進時載入房型加成，傳給模擬器。

**Tech Stack:** 沿用（.NET 10、EF Core Database-First、Flyway、MySQL 8.4、xUnit v3＋Testcontainers、React 19、Vitest）。

**Spec:** `docs/superpowers/specs/2026-10-29-inn-design.md`

- **房型內容**（`backend/content/inn.json`；`Tests/TestContent/inn.json` 放同一份）：
  ```json
  { "seconds": 28800, "pricePerLevel": 50, "rooms": [
    { "id": "apprentice-loft",  "name": "學徒閣樓", "kind": "Exp",          "multiplier": 1.10, "priceRate": 2 },
    { "id": "training-chamber", "name": "修練廂房", "kind": "JobExp",       "multiplier": 1.10, "priceRate": 2 },
    { "id": "fighters-bunk",    "name": "鬥士通鋪", "kind": "Attack",       "multiplier": 1.05, "priceRate": 1 },
    { "id": "stargazer-tower",  "name": "星見塔房", "kind": "Magic",        "multiplier": 1.05, "priceRate": 1 },
    { "id": "bulwark-room",     "name": "鐵壁客房", "kind": "Defense",      "multiplier": 1.05, "priceRate": 1 },
    { "id": "quiet-chapel",     "name": "靜謐禱室", "kind": "MagicDefense", "multiplier": 1.05, "priceRate": 1 } ] }
  ```
  載入驗證：
  - multiplier 1.01～3.00，小數最多兩位，沿用密藥的常數。
  - seconds 60～86 400。
  - priceRate ≥ 1，pricePerLevel ≥ 1。
  - id 不重複，rooms 不可為空。
- **價格**：`(long)等級 × pricePerLevel × priceRate`。手動入住一律收費。
- **倍率相乘**：
  - 公式：`倍率 = Buffs.Multiplier(密藥, kind, t) × (房型加成在 t 生效且同 kind ? 房型倍率 : 1)`。
  - 相乘後只取整一次，取整方式沿用現有的 `Buffs.Scale` 與 `RoundLikePhp`。
  - 範例：經驗基數 100，經驗密藥 1.5，學徒閣樓 1.10 → 165。
- **入住順序**：
  1. 驗證房型存在，不存在 → 400 `unknownRoom`。
  2. 驗證錢夠，不夠 → 400 `notEnoughMoney`。
  3. `AdvanceAsync` 結算。
  4. 用結算後的角色重新計算價格（結算中可能升級），再檢查一次錢；不夠 → 400 `notEnoughMoney`，整筆回滾。
  5. 寫入：扣錢；HP、SP 回滿到含裝備的上限；房型加成**整筆取代**舊的，`StartsAt = now`、`EndsAt = now + seconds`。
- **前端文案**

  | 用在哪 | 文字 |
  |---|---|
  | 子頁按鈕 | 旅館 |
  | 區塊標題 | 目前入住、客房、自動住宿 |
  | 加成列 | `{房名}・{經驗｜熟練度｜物攻｜魔攻｜物防｜魔防} ×{倍率}（剩 {h}:{mm}）`，剩餘分鐘無條件進位 |
  | 沒有加成 | 目前沒有住宿加成（旅館頁）；角色頁不顯示 |
  | 入住鈕 | 入住；錢不夠時停用，不顯示差額 |
  | 取代提示 | 會取代目前的{房名} |
  | 錯誤原因 | `unknownRoom` → 沒有這個房間；`notEnoughMoney` → 沿用既有文案 |

- 程式碼註解用中文，非必要不寫。commit 用英文 Conventional Commits 加 emoji，不加 trailer。結構性與行為性變更分開 commit。

## Review Focus

- **入住前有尚未結算的冒險時間**：新加成不能套到入住之前開打的場次；結算時自動住宿花掉了錢，導致入住時錢不夠，就整筆不寫。→ Task 4 `Book_DoesNotBoostFightsBeforeBooking`、`Book_RechecksMoneyAfterSettling`。
- **房型加成跟同種密藥同時生效**：兩者要相乘，不是取大的那個；房型加成到期後只剩密藥。→ Task 1 `Combined_MultipliesElixirAndLodging`、Task 2 `Adventure_LodgingAndElixirMultiply`。
- **內容檔移除了玩家正在住的房型**：`GET /api/inn`、推進都照常回 200，加成視為不存在。→ Task 4 `Get_IgnoresLodgingForRemovedRoom`、Task 2 `Adventure_NoLodgingKeepsRollSequence`。
- **連續換房**：新房間取代舊房間，時間重新計算為 8 小時，舊房間的加成立刻失效。→ Task 1 `Book_ReplacesLodgingAndRestartsTimer`、Task 4 `Book_ReplacesPreviousRoom`。
